# Behaviors — boilerlab.ai (`/`)

## Global interaction model
**INTERACTION MODEL: click/keyboard/wheel-driven slide deck (not document scroll).** The whole page is locked to `100dvh`/`overflow:hidden`. Mouse wheel, ArrowLeft/ArrowRight (and Up/Down for the "numbers" vertical group), swipe, and footer-nav clicks all advance/retreat a single slide index. There is no scroll-triggered header shrink, no IntersectionObserver-based section reveal — sections become visible strictly through slide-index transitions.

## Slide transition behaviors (re-verified with instrumented timing, not just static CSS)
**Update (re-verification pass):** side-by-side timing tests against the live site — real `.click()` on footer-nav links vs. synthetic `ArrowRight`/`wheel` events, with computed `opacity` sampled every ~20ms across the whole transition inside one continuous in-page loop (to avoid cross-tool-call latency skewing the numbers) — found the split is by **trigger method**, not by same-topic vs. cross-topic as first assumed:
- **Footer-nav link click** (any pair, e.g. mission→numbers): consistently ~0.68-0.70s total. This matches `slide-in-fade`/`slide-out-fade`, `var(--transition-wheel)` = 0.68s, `cubic-bezier(.16,1,.3,1)` — a plain cross-fade.
- **Keyboard ArrowRight/Left AND mouse wheel** (tested both a same-topic hop — numbers-intro → numbers-stat1 — and a cross-topic hop — numbers-stat2 → partners): both consistently ~1.15-1.2s, matching `var(--transition-horizontal)` = 1.15s. The incoming section sits at a constant `matrix3d(0.4,0,0,0, 0,0.4,0,0, 0,0,1,0, 0,0,-1500,1)` (scale 0.4, translateZ -1500px — the `slide-in-fwd-center`/`slide-out-fwd-center` "parked" state referenced by class name but with no matching `@keyframes` in the shipped CSS) at `opacity:0` for nearly the whole duration, then flips to `opacity:1`/`transform:none` right at the end — sampled at 20ms resolution with zero intermediate opacity values in between. This could be a real "hold then instant reveal" effect, or it could be this test environment's rAF throttling (confirmed separately: `requestAnimationFrame` in this automated browser fires as rarely as ~1.5 Hz even on the foregrounded tab) masking a JS/rAF-driven smooth interpolation that a real user's browser would render continuously. Either way, the **total duration (~1.15-1.2s) is reliable** even though the exact smoothness of the middle of it isn't fully verifiable from this harness.
- I found **no evidence** of a distinct "vertical" treatment (`slide-in-bottom`/`slide-out-top`, `var(--transition-vertical-move)` = 1.18s) for same-topic keyboard/wheel steps specifically — the numbers-intro→numbers-stat1 hop measured identically to the cross-topic hop. Those keyframes are real (extracted from source CSS, kept in `boilerlab.css` as dead code) but nothing in this deck's actual arrow-key/wheel navigation appeared to trigger them; they may be reserved for touch swipe or an untested Up/Down-arrow path.
- Partners → Products transition specifically uses a delayed fade-in (`slide-in-fade-after`, delay `var(--transition-partners-products-fade-delay)` = 0.68s, duration `var(--transition-partners-products-fade)` = 0.54s) so the outgoing partners slide's marquee settles before products fades in — this held regardless of trigger method in testing, so the clone applies it unconditionally for that specific pair.
- Starfield opacity: `#star-canvas` fades in over `var(--transition-stars-fade-in)` = 0.12s and fades out over `var(--transition-stars-fade-out)` = 0.52s (`.stars-hidden` class), decoupled from slide content transitions — implies the starfield is hidden/dimmed behind slides that have their own background treatment (products/in-press/contacts) and restored for the plain star-slides (mission, numbers, partners).

**Clone implementation:** `BoilerLabApp.tsx`'s `navigate(index, trigger)` now takes `trigger: "nav" | "step"` — footer-nav clicks pass `"nav"` (0.68s fade), keyboard/wheel pass `"step"` (the default, 1.15-1.2s fwd style) for every pair, with the partners→products pair special-cased regardless of trigger.

## Typewriter text effect
**INTERACTION MODEL: time-driven, triggered on slide becoming present.** Elements with `data-typewriter` (numbers slide's two paragraphs; contacts slide's 5 address lines via `data-typewriter-deferred` on the wrapper) get their text split into `<span class="typewriter-word"><span class="typewriter-letter" style="animation-delay:Nms">`. Each letter fades in (`opacity 0→1`, `.22s ease-out`) with `animation-delay` incrementing **18ms per letter** (word-boundary spaces get an extra ~18ms gap — e.g. word 1 ends at 72ms, word 2 starts at 108ms, a ~36ms gap). Once complete, the paragraph gets class `is-typed` and delays are left in place (letters stay opacity:1, `animation:none`). Contacts detail lines add a blinking text-cursor (`.is-typing-machine:after`, `step-end infinite alternate`, 0.53s) on whichever line is actively typing.

## Products slide — internal card stack
**INTERACTION MODEL: scroll-driven (NOT click-to-switch), internal to the slide, distinct from the reveal.js slide index.** Desktop (>820px): all 9 `<article class="product-card">` are absolutely centered (`top:50%;left:50%;transform:translate3d(-50%,-50%,0)`) inside `.product-content{perspective:75rem; transform-style:preserve-3d}`. A wheel/scroll gesture while this slide is present moves cards along the Y axis in vh units (observed offsets: focused card `0px`/`-1.78vh`, next card `+58.7vh`, following cards `+120vh`/`+122vh`) with per-card inline custom properties `--card-dim` (0 → ~1, drives a `:after` black overlay opacity) and `--card-blur` (0 → several px, blurs `.product-copy`/`.product-visual-image` via `filter:blur(var(--card-blur))`) that increase with distance from center, plus `scale` shrinking slightly (1.0 → 0.86) and `opacity` dropping to 0 with `visibility:hidden` once far enough off-center (also toggles `pointer-events` so far cards aren't clickable). Only after scrolling through all 9 cards does further wheel input advance the outer slide deck to "in-press".
Mobile (≤820px): this entire mechanism is disabled — cards render `position:relative`, `transform:none!important`, `opacity:1!important`, `filter:none!important`, stacked in normal document flow inside a scrollable slide (`overflow:hidden auto` on the section itself, masked top/bottom with a linear-gradient fade).

## Partners slide — expanding logo panel
**INTERACTION MODEL: state-class-driven (added when slide becomes present, not scroll/click).** On enter, section gets `.partners-open` (then `.partners-leaving` on exit, briefly `.partners-settle` if re-entered quickly):
1. Hero copy (`.partners-hero-copy`) rises `translateY(-7.125rem)` starting at 0.48s, over 0.72s.
2. The showcase frame (`.partners-showcase-frame`, starts as a 1.125rem-wide vertical strip with 4 corner "node" squares) widens to its full panel width (`min(47.5rem, 100vw - 4.5rem)`) starting at 1.18s over 0.84s, opacity fading in first (1.08s, 0.2s).
3. Corner-gradient masks, the "Our partners and clients:" label, and the logo marquee viewport fade/rise in together starting at 1.42s over 0.48s.
4. The logo marquee itself auto-scrolls continuously and independently: `.partners-logos-track{animation:partners-logos-scroll 24s linear infinite}`, translating `0 → -33.3333%` (the logo `<ul>` is tripled in the DOM for a seamless loop).
Leaving/re-entering quickly collapses all these transitions to a flat 0.32s (`--partners-settle-duration`).

## In-press slide — floating cards
**INTERACTION MODEL: time-driven ambient animation + entrance animation, static positions (not scroll or click-driven).** Each of the 7 `.in-press-card` anchors has fixed inline `--press-left/--press-top/--press-width/--press-rotate/--press-z/--press-delay/--press-duration/--press-index` (hand-authored scattered layout, not computed). All cards continuously float via `animation:in-press-float var(--press-duration) ease-in-out var(--press-delay) infinite alternate` (a subtle vertical bob, duration/delay vary per card 7.4s–10s so they're out of phase). On slide becoming present: title does `in-press-title-in` (0.62s, 80ms delay) and each card does `in-press-card-in` (0.76s, staggered `calc(0.44s + var(--press-index)*95ms)`) — both "backwards" fill so they start from their 0% keyframe state, not the page's initial state. Cards have a hover-lift (desktop, `hover:hover` media): scale/shadow increase on `.in-press-card-surface`, only active with fine pointer + hover capability (excluded on touch).

## Contacts slide — arriving moon
**INTERACTION MODEL: entrance-animation, triggered once on first arrival at this slide (`.contacts-arriving` class), not scroll-linked.** The full-moon image sits absolutely behind the content (`top:100%`, shifted up 50% of its own height so only the top ~third pole is visible, like a horizon). On first arrival it plays `moon-arrive-rise` (rises from `translate3d(0, calc(-50% + 16vh), 0) scale(.84)` to its resting `translate3d(0,-50%,0) scale(1)`) simultaneously with `moon-arrive-glow` (brightness/contrast pulse) and the title's `contacts-title-arrive` (blur-in + fade), all sharing `var(--moon-arrive)` = 2.4s, `cubic-bezier(.16,1,.3,1)`. After arriving, the moon continuously rotates forever at `moon-rotate 1000s linear infinite` (i.e., visually static — a 1000-second rotation is imperceptible; it exists presumably for subtle parallax/consistency, not a visible spin). `prefers-reduced-motion: reduce` disables all of the above (no animation, resting state only).

## Sound toggle
Header button `.sound-toggle` (`aria-pressed` true/false) toggles an ambient audio track (`ambient.mp3`, loaded lazily) muted/unmuted; label text flips "SOUND: OFF" / "SOUND: ON" (desktop shows the text label; mobile ≤760px hides the label and shows only an icon, swapped via `[aria-pressed=true] .sound-toggle-icon-on` / `[aria-pressed=false] .sound-toggle-icon-off`).

## Footer nav active-state sync
Clicking a footer-nav link jumps directly to that slide/topic. The link matching the current topic gets `.is-active`: color goes solid white, font-size grows via `clamp(1.25rem, 2vw, 1.75rem)`, and its label lifts `translateY(-0.42em)` — all transitioning over 0.3s ease-out. This must be kept in sync with the current slide's `data-section-id` (or own id) on every slide-change event, including the 3 "numbers" sub-slides which all map back to the same "NUMBERS" footer link.

## Buttons — hover/active (desktop, `hover:hover and pointer:fine` only)
- **Primary** (white pill): base has a diagonal light-sweep pseudo-element parked off-canvas; hover raises box-shadow + `scale:1.04` + `brightness(1.03)` and sweeps the highlight across (1.1s); active/press drops to `scale:.96`, darker `#d6d6d6` background, fast 80ms transition.
- **Secondary** (translucent header pill, e.g. sound toggle): hover lightens background/shadow + `scale:1.03`; active dims further + `scale:.96`.
- Footer-nav links: hover tints text to `--accent` (#eef2ff), no size change (only `.is-active` changes size).

## Responsive sweep summary
Tested breakpoints via the CSS media queries (not manual DevTools resize, since layout is CSS-driven and declared exactly): 1440 (base fluid scale), 1180 (product alignment), 1000 (product density), 820 (**products loses its scroll-jacked 3D stack entirely — becomes a plain vertical list**), 760 (broad mobile overrides: header/footer sizing, hero/mission typography, partners panel proportions, contacts moon width, button sizing, footer-nav becomes a horizontally-scrollable row of equal-opacity pills that only fully scale up the active one).
